# UX QA Pass — 2026-05-04

## Scope

End-to-end browser QA for the designer workflow after the initial MVP build:

1. Sign in.
2. Create a Dubai residential project.
3. Add a room photograph.
4. Remove an uploaded photograph.
5. Save a design brief with measurements and budget.
6. Generate an initial concept.
7. Select the concept.
8. Run product matching from ingested catalog data.
9. Try product substitution.
10. Generate a final grounded render.

## Sample Brief

- Project: Al Barari UX QA Villa
- Client: Noura Residence
- Location: Dubai
- Budget: AED 35,000–65,000
- Room: Main Living Room
- Room type: living room
- Style: warm contemporary Dubai villa, editorial but practical for a family living room.
- Colour: bone, warm paper, walnut, muted ochre, olive accents, textured linen.
- Budget notes: prioritise sofa, rug, coffee table, and lighting; save on armchairs and decor if needed.
- Functional requirements: seating for six, child-safe coffee table, durable fabric, practical side table, clear circulation to balcony doors.
- Avoid: glass coffee table, high-pile rug, mirrored furniture, generic hotel-lobby gold finishes.
- Measurements: main wall 520 cm, room depth 410 cm, ceiling 300 cm.

## Failures And Friction Found

- Uploaded photographs had no visible removal action.
- Long server actions looked stalled because buttons did not enter a local pending state.
- Primary buttons became visually weaker on hover, which made the active action less clear.
- The brief page used `Generate concepts` for an action that actually saves the brief and prepares clarifying questions.
- Product cards repeated the same dimension warning because dimension fit was stored in both `dimension_fit_note` and `selection_reason`.
- The local test project initially had no catalog products, so product matching correctly failed with `No catalog products are available yet. Run ingestion first.`

## Fixes Applied

- Added a reusable `SubmitButton` component based on `useFormStatus`.
- Added pending labels for sign in, account creation, project creation, brief save, answer save, concept generation, concept selection, revision generation, product matching, product swapping, photo removal, and final render generation.
- Changed primary button hover to stay filled instead of becoming transparent.
- Added `deleteRoomPhotoAction` and visible `Remove` controls on uploaded room photographs.
- Added upload progress copy for multi-image uploads.
- Changed brief CTA copy from `Generate concepts` to `Save brief`.
- Removed duplicate dimension warnings from newly generated shopping-list items.
- Tightened dimension parsing so product names or URLs with numbers are not treated as verified dimensions unless there is a dimension signal.

## Remaining Product Risks

- AI calls still block the request while running. Button-level feedback is now clear, but the production UX should move long AI actions to background jobs with polling and durable progress.
- The QA catalog had only a small Home Centre sample, so product matching over-selected sofas. Broader scheduled ingestion is needed for representative category coverage.
- Many Home Centre product pages do not expose dimensions in usable structured data. The UI now states fit is assumed when dimensions are missing.

## Visual Grounding Patch

Founder review identified a workflow mismatch: the shopping list was product-backed, but the listed products were not sufficiently tied to the approved concept image, and the final render could still drift from the shopping list.

Fixes applied:

- Product matching now sends the approved concept render to a visual sourcing assistant.
- The sourcing assistant extracts visible product roles and visual briefs from the concept image.
- Candidate product image URLs are included in the sourcing pass so selection considers visual similarity, not only concept text.
- Shopping-list lines now include `visual match:` and `mismatch:` reasoning when the selected product is a close substitute rather than an exact match.
- The final render call now includes the original room photo, the approved concept image, and selected product images.
- Final render prompting now explicitly forbids introducing alternate main furniture/decor not represented in the selected catalog references.
- Image 2 compatibility fixed: `input_fidelity` is omitted for `gpt-image-2`, which does not support that parameter.

Runtime verification:

- Browser product matching produced visual match/mismatch notes for the current QA project.
- Browser final render retry completed with latest render job `succeeded`.

- Shopping-list and presentation prices now prefer refreshed catalog sale/current prices before falling back to the stored draft line total.
- Suppressed stale `Dimensions missing` fit notes when verified catalog dimensions are now present.
