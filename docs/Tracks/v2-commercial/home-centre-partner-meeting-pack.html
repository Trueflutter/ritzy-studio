Findings From Live Site Review

Confirmed

  • Product pages can be deep-linked directly.
  • Product IDs are visible in URLs, e.g. 166839119.
  • SKU-like identifiers are present in page state.
  • Users can add products to basket before signing in.
  • Anonymous basket persists through the current browser session.
  • Checkout first routes to sign-in, but offers Checkout As A Guest.
  • Cart and guest checkout both include Promos & Vouchers.
  • Checkout remains fully hosted by Home Centre.

Not confirmed publicly

  • Whether Home Centre supports public add-to-cart URLs.
  • Whether promo codes can be automatically applied from URL parameters.
  • Whether partner metadata can be stored on a cart/order today.
  • How long anonymous carts persist after browser close.
  • Whether anonymous carts merge into accounts after later sign-in.
  • Whether Home Centre has an existing public partner API.
Important technical nuance: public JavaScript assets show internal cart, checkout, offer-code, SKU, inventory, and delivery estimate API routes. That means the capability likely exists inside Home Centre's stack. Ritzy should not use or imply it will use those internal APIs without an approved partner endpoint, signed link, or formal integration agreement.

Updated recommendation: do not assume Home Centre needs a completely custom commercial route. There is documented evidence that Home Centre has used an affiliate network route before. Sam should ask whether that program can be reactivated or whether Ritzy should be set up as a direct strategic partner outside the standard affiliate channel.

Home Centre: DCMnetwork affiliate listing

DCMnetwork lists a Home Centre Affiliate Program covering UAE, Bahrain, and Saudi Arabia. The page says affiliates can get tracking links, create deep links, request exclusive coupon codes, and view conversion reports.

The key limitation: the listed campaign status is Paused, and commission details require publisher registration. The listing also says sales are tracked from coupon attribution and that coupon codes are best for promoting the offer.

Commercial Ask

Traffic commitment

Ritzy can position this as a demand-generation partnership: up to AED 50,000/month in paid advertising to send qualified UAE homeowners and designers to Home Centre products.

Customer offer

Request a 5% customer discount on eligible products or selected categories, ideally applied automatically or via a campaign-specific code.

Ritzy economics

Request a 5% commission to Ritzy on attributed completed orders, with clear rules for returns, cancellations, taxes, delivery charges, and partial refunds.

Commercial details Sam should confirm

  • Does the 5% customer discount apply to all products, selected categories, or a curated SKU set?
  • Does the discount stack with current sale prices?
  • Is the code public, hidden, single-use, multi-use, session-bound, or customer-bound?
  • Can Home Centre create campaign-specific codes for Ritzy?
  • What is the attribution window: same session, 7 days, 14 days, 30 days?
  • Is Ritzy paid on gross order value, net sales, or net of returns/cancellations?
  • Can Ritzy advertise "partner pricing" or only "retailer links"?
  • Can Ritzy use Home Centre product images, brand name, and logo inside the app?
  • What reporting fields will Home Centre provide, and at what cadence?

Technical Ask and Safety Reassurance

What Ritzy needs technically

  • Confirmed product identifier to store: SKU, variant SKU, parent SKU, or internal product ID.
  • Product feed with URL, title, images, price, sale price, stock, dimensions, colour, material, category, and delivery/assembly flags.
  • Inventory/price refresh mechanism: API, SFTP, feed, or scheduled export.
  • Partner tracking method: UTM, affiliate link, campaign ID, partner ID, or signed token.
  • Discount application method: manual code, URL auto-apply, hidden server-side code, or partner entitlement.
  • Order reporting by partner/campaign ID, ideally including SKU-level line items.

Why this is safe for Home Centre

  • Home Centre owns checkout and payment.
  • Ritzy never stores card numbers or payment credentials.
  • Ritzy never asks for Home Centre account passwords.
  • Home Centre validates stock, price, delivery eligibility, and fulfillment rules.
  • Home Centre can cap, expire, rotate, or revoke partner codes.
  • Home Centre can restrict discounts by SKU, category, geography, user, or campaign.
  • Home Centre can reject unavailable items before checkout starts.

Checklist for Home Centre product/engineering

Question Why it matters
Do you support cart creation links? Lets Ritzy send a user directly to a prepared cart instead of only a PDP.
Do you support adding SKUs to cart via URL? Lowest-effort cart-prefill option if an API is not available.
Do you support pre-applied promo codes via URL? Improves UX and avoids manual code copying.
Can a partner code be applied invisibly server-side? Lets Home Centre hide, rotate, and control discount mechanics.
Can you create a hosted checkout/cart session by API? Best V1 experience: Ritzy sends SKU/qty; Home Centre returns URL.
Can you attach partner ID, campaign ID, and Ritzy project/room ID? Enables attribution, reporting, and order reconciliation.
What authentication is required? API key, OAuth, signed URL, HMAC, IP allowlist, rate limits, sandbox.
Can unavailable items be returned before checkout? Prevents customers landing on broken or out-of-stock carts.

Suggested App Flow

User finishes a room design. Ritzy shows the final render and selected product list after the shopping-list unlock.
Ritzy groups products by retailer. If all selected items are Home Centre, show one primary action: Checkout with Home Centre.
Ritzy creates the outbound purchase session. In the ideal flow, Ritzy sends SKU, quantity, campaign ID, and room metadata to Home Centre. Home Centre returns a hosted cart/checkout URL.
User lands on Home Centre. The cart or checkout is prepared by Home Centre. The user completes address, delivery, promo, payment, and order confirmation there.
Ritzy logs attribution. Ritzy records outbound click/session: project ID, room ID, products, retailer, timestamp, campaign ID, and checkout URL type.
Orders are reconciled later. If Home Centre provides reports, Ritzy matches order IDs and SKU line items back to campaign/project metadata.

If a Room Mixes Retailers

Mixed-retailer rooms should not force one universal checkout in V1. That would make Ritzy look like the merchant of record and create avoidable payment, support, returns, inventory, and legal complexity.

V1: retailer groups

Show the shopping list grouped by retailer: Home Centre, IKEA, Pan Emirates, etc. Each group has its own checkout button.

Example: "Checkout 4 items with Home Centre" and "Shop 2 items at IKEA."

V1.5: preferred retailer mode

Let users choose "prioritise Home Centre" so Ritzy biases product matching toward one retailer and reduces fragmented checkouts.

This is commercially useful if Home Centre gives better pricing, commission, or feed quality.

Later: Ritzy orchestration

If multiple retailers provide checkout-session APIs, Ritzy can create several hosted checkout sessions and present a step-by-step purchase plan.

Still no payment handling by Ritzy unless the business chooses a marketplace model later.

Do not promise a universal multi-retailer cart for V1. Promise retailer-hosted checkout sessions. If a design contains multiple retailers, the honest V1 is multiple retailer checkout buttons grouped cleanly in the shopping list.

Bottom Line

Home Centre is a strong first target because its current customer journey already supports the behaviors Ritzy needs: stable product links, anonymous basket, guest checkout, voucher entry, SKU visibility, and retailer-hosted payment. Ritzy should make the commercial ask clearly, keep the technical ask safe, and avoid over-promising a marketplace or universal cart before the partner infrastructure exists.
